# PIL-446: actual-client responsiveness under staging load

[Client issue](https://linear.app/pilah-2/issue/PIL-446)

The backend repository's `tests/load/README.md` owns fixture preparation, k6 load,
thresholds, integrity auditing and cleanup. This document owns client observations.

## Build and identify the native client

Use an isolated checkout of `staging`. Copy ignored `.env` and Android Firebase
configuration with the workspace's localhost helper. Set only that checkout's
`BASE_URL_DEV` to `https://pilah-be-staging.fly.dev` (no trailing slash) and disable demo login.
Do not change production configuration or commit the local configuration.

```bash
flutter pub get
flutter build apk --debug -t lib/main_development.dart
agent-device boot --platform android --device medium_phone --headless
agent-device reinstall com.mobile.pilahapp build/app/outputs/flutter-apk/app-debug.apk --platform android --device medium_phone
agent-device open com.mobile.pilahapp --platform android --device medium_phone --foreground
```

Verify the APK's configured development destination before submitting credentials.
Record its SHA-256, source revision, build mode, Flutter version, device/emulator,
Android version and network conditions. A debug build/emulator observation is not a
release-build or physical-device performance claim. Keep boot/cold-start delays
separate from an already-open screen's action timings.

## Keep total concurrency exact

Run one real client at a time. The backend `probe` action reserves one matching
virtual-user slot. At totals 10/20/30, use the last selected Pengurus account
(indices 6/13/20 in the private manifest), or Nasabah account (23/26/29).
Do not use production or shared demo accounts.

For a Pengurus probe, declare one actual-client write using `--probe-writes 1`;
Nasabah probes are read-only. The post-run audit adds that expected write to k6
creates and verifies the persisted count/balances. Retain the saved transaction ID
in the synthetic evidence. Do not reset the dataset until auditing completes.

## Observe and measure

Use `playwright-cli` for desktop web and `agent-device` for Android native.
For Flutter web, enable the visible accessibility placeholder before locating the
controls. Wait for named final content; a changed route or stopped spinner alone
is insufficient. Record time from click/tap to the expected content or saved
confirmation, including any tool overhead as a conservative upper bound.

Pengurus web/native:

1. Search for a synthetic nasabah and open their detail.
2. Create one setoran: 1 kg of Load Plastik at the fixture's price.
3. Verify the saved confirmation/record, recipient and Rp 2,500 amount.
4. Open jadwal and riwayat and verify the synthetic schedule and saved record.

Nasabah native:

1. Verify the signed-in customer's balance.
2. Open jadwal and personal riwayat.
3. Verify that the account and membership remain the expected synthetic identity.

Never send a WhatsApp receipt or load-test Google sign-in. Nasabah web is excluded.
The observed action target is ≤3 seconds. Report every sample; a few observations
do not establish a reliable client p95. Also capture client console/app errors,
synthetic-only screenshots and timestamps aligned to the backend trial.

If 10 users fail the backend targets, record the failure and investigate before
escalating to 20/30. Client probes at that level remain diagnostic; do not present
them as overall passing capacity. Review the evidence with Tristan before marking
the client issue complete.

## Recorded first execution

See the [staging evidence](https://linear.app/pilah-2/document/pil-393-staging-load-test-evidence-7086e4575a96) for individual observations and limitations.
The backend failed read targets at 10 users, so 20/30 are untested. The deployed
setoran picker searches only its first 100 active members; [PIL-449](https://linear.app/pilah-2/issue/PIL-449)
tracks the functional limit. A successful screen check does not override a failed
backend capacity level. Tristan confirmed that the tested journeys match busy-day usage. Capacity
acceptance remains blocked by failed read targets.
