# PIL-246: report activity filters and pagination

Base: `origin/feature/pil-315` at `b832d786556c300120703791351cc848d1e7888a`.
Implementation branch: `feature/pil-246`.

The pengurus Laporan page now uses `GET /api/v1/aktivitas`, rather than fetching
and merging two independently paginated lists. Period, custom date range,
activity type and name search are sent to the server. Next pages append to the
same ordered feed and deduplicate by type plus ID. Scrolling near the bottom
loads another page; a button also permits explicit load/retry.

Initial loading, empty, initial failure, next-page loading and retry states are
handled separately. Next-page failure keeps existing rows and retries the same
page. Generation tokens prevent stale responses from changing a newer filter
or repopulating a logged-out session.

Day/week/current month/previous month/rolling 3, 6 and 12 month filters and
custom dates are supported. Filter chips scroll horizontally; type chips wrap
on narrow screens. Existing detail sheets remain available for both types.
Both activity types display local dates as `DD/MM/YYYY` above `HH:mm`, keeping
the timestamp readable on narrow screens.
XLSX still exports setoran and is labeled `XLS Setoran`; combined XLSX belongs
to PIL-248. The PIL-315 nasabah screen retains its existing history contract.
